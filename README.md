# SceneRecall 0.2

本地影视资料库：把电影、动画、剧集中的画面、人物、动作、物体、位置和台词保存为带时间证据的记录，再用自然语言找回片段，回到原片核对、收藏和引用。

这是单用户本地网页应用，采用 Python / FastAPI、React / TypeScript、FFmpeg、PySceneDetect、SQLite FTS5 和 LanceDB。识别与检索的 AI 接口独立配置；可以接入自备 API，或通过本机 Codex CLI 使用已登录账户的 Codex 订阅额度。JSON / JSONL 是长期资料，检索索引可以重建。

**容器文本字幕已完成十二集真实 MKV 验证：24 条 ASS 轨、17,088 条文本记录与原始字幕包逐条匹配，时间偏差为 0 ms。** 分块流程已完成同配置 Codex 短片段对照，模型耗时降低 55.5%，八条检索样本通过；整片识别准确率、OCR 准确率和费用仍待验收，详见[验证记录](docs/VALIDATION.md)。

## 启动

需要 Python 3.12 或 3.13、[uv](https://docs.astral.sh/uv/)、Node.js / npm，以及能在终端找到的 `ffmpeg` 和 `ffprobe`。推荐使用本次验证的 Python 3.12 与 Node.js 22；首次安装依赖需要网络。macOS 优先验证，Windows / Linux 尚未完成平台验收。

在项目根目录执行：

```sh
uv sync --python 3.12 --extra dev
cd frontend
npm install
npm run build
cd ..
uv run scenerecall --data-dir "$HOME/SceneRecallLibrary" --port 8765
```

如果默认 uv 缓存目录不可写，可只对安装命令指定可写缓存：

```sh
UV_CACHE_DIR=/tmp/scenerecall-uv-cache uv sync --python 3.12 --extra dev
```

打开终端打印的完整链接，例如 `http://127.0.0.1:8765/?token=…`。浏览器用该令牌建立本机会话，随后移除地址中的令牌。**这不是 AI API Key**；重启服务会生成新令牌，需要使用新链接。启动命令也可写成 `uv run scenerecall start --data-dir "$HOME/SceneRecallLibrary" --port 8765`。

默认资料目录是 `~/SceneRecallLibrary`，可用 `--data-dir` 指定其他目录。服务只监听 `127.0.0.1`；前端构建后由同一服务提供，不需要另起网页服务器。不要把本机会话链接分享给他人。

## 停止

在项目根目录新开一个终端执行，无需查找 PID：

```sh
uv run scenerecall stop
```

这会停止使用默认资料目录 `~/SceneRecallLibrary`、端口 `8765` 的服务。自定义启动参数时，停止命令使用相同的资料目录和端口：

```sh
uv run scenerecall stop --data-dir "/path/to/library" --port 8877
```

可先加 `--dry-run` 只检查目标；`--timeout 60` 将正常退出的等待时间延长至 60 秒（默认 30 秒）。停止命令目前支持 macOS / Linux，通过当前 Python 环境中 `scenerecall` 入口启动的实例；启动终端仍可按 `Ctrl+C` 退出。用 `python -m`、直接调用 Uvicorn 或其他环境启动的实例，请回到对应启动终端操作。

命令每次核对系统用户、当前安装入口、Python 解释器、资料目录和实际监听端口，再发送正常退出信号并等待进程结束；同一项目此前通过上述入口启动的服务也可识别，无需先重启。不会根据旧 PID 文件或仅凭端口杀进程。输出「已停止」或「未运行」时退出码为 0；身份不符、端口被其他程序占用、权限不足、多个匹配实例或等待超时会给出原因并返回非零退出码。超时不会强制终止，请检查启动终端或稍后重试。

停止保留影片资料、索引、任务记录和持久化配置；再次运行启动命令即可继续使用。运行中的任务按现有队列机制保存／恢复，已发送的模型请求可能已产生用量。仅在服务会话中保存的 API Key 与浏览器登录令牌在重启后需要重新填写／获取。

## 第一次使用

1. 如需画面理解、画面 OCR 或 AI 检索，在「模型与设置」添加连接；本地文本字幕提取和字面检索无需模型。添加连接时，选择 API 或 Codex CLI。API 连接填写名称、Base URL、模型 ID、支持的能力及 API Key；Base URL 填到接口根地址（通常包含 `/v1`），不要填写完整的 `/chat/completions` 路径。Codex CLI 先按下文安装并登录。保存后按能力进行连接测试；测试会实际调用所选服务。
2. 在能力分配中选择各阶段的连接，再保存。新版画面分析需要「分块与简要索引 `preparation`」和「画面理解 `vision`」；前者可绑定较快的视觉模型，后者负责深入理解。两项可共用一个声明了这两种能力的连接，字幕 OCR 仍可单独配置。
3. 「导入作品」中浏览本机目录并勾选多个视频，或一次粘贴多行**本机绝对路径**。选择剧集／动画项目，逐集核对标题、季／集、版本和字幕；可批量填写季号和连续集号。原视频保留原位置，不上传或复制整集。
4. 默认自动探测视频内的字幕轨，优先本地提取文本字幕，也可探测后按语言、名称、编码和默认标记选择轨道。外挂模式需提供 SRT、VTT 或 ASS；确实烧录在画面中的文字仍可选择画面 OCR。无字幕轨的自动导入会保留为待 OCR，分析前再配置模型。
5. 导入完成后选择「分析这批视频」，或在项目中勾选多集分析。可先试前 60 秒或自选短片段；先在本地扫描内容关键帧，查看预览和分阶段用量范围，再开始「台词整理 → 视觉分块 → 复杂片段深入理解」。可分别选择台词整理、视觉分块与字幕 OCR 的并行／串行方式和最大并行数。每集独立设置预算，整批汇总用量；支持暂停、恢复、取消与失败重试。
6. 到「自然语言检索」输入台词、剧情、人物外观或画面描述。场景结果标明「初步理解／深入理解」，可展开查看画面事实、台词事实和综合推断。需要补查时点击「深入分析此片段」，估算并设置预算后加入任务队列；搜索不会自动启动画面分析。仍可纠错、确认人物姓名、添加笔记与收藏，导出 Markdown / JSON 引用清单。

| 能力 | 发送给所选服务的数据 | 未配置时 |
| --- | --- | --- |
| 分块与简要索引 `preparation` | 当前字幕、编号关键帧预览拼图、此前连续理解和相关角色档案；需要时仅发送文字更新后续理解 | 不能启动界面中的新分块分析；旧任务和已有片段补查不因此失效 |
| 画面理解 `vision` | 当前片段的原始关键帧、时间戳、对应台词、此前记忆及同项目角色档案／参考图 | 不能执行深入理解或片段补查 |
| 画面字幕 OCR `subtitle` | 字幕区域裁剪图及时间戳 | 不能执行画面字幕识别；本地文本字幕轨提取不受影响 |
| 语义向量 `embedding` | 已保存的描述／字幕及查询文本 | 使用字面检索，显示降级提示 |
| 查询理解 `query` | 用户问题 | 使用本地查询处理 |
| 决策重排 `decision` | 用户问题与有限候选证据 | 使用本地排序 |
| 结果解释 `answer` | 用户问题与候选证据 | 使用模板解释 |

API 连接支持 OpenAI-compatible 的图像消息、文本消息和 embedding 接口。Codex CLI 支持分块与简要索引、画面理解、内嵌字幕、查询理解、决策重排和结果解释，不提供 embedding；语义向量可单独绑定 API，或留空使用字面检索。`preparation` 同时需要文字和图像理解能力。服务必须真正支持所绑定的能力；勾选能力不代表模型自动获得该能力。Jev 的位置是 `DecisionProvider`，当前实现使用传统 LLM，尚未接入 Jev 服务。

## 字幕引导的分块索引与连续理解

界面新建的画面任务使用 `scene-chunks-v1`，复用已完成的本地关键帧计划，保留全部选中原帧。已有容器／外挂字幕先按原始字幕 ID 和时间轴整理话题与事件；若本次勾选了烧录字幕 OCR，则先完成 OCR。无台词区段同样参加画面分块。

快速视觉模型每批检查最多 **56 张新关键帧＋8 张前批边界参考帧**，通过带编号和时间码的拼图给相邻画面分块、选择代表帧并建立简要索引。同一对话的正反打可跨镜头合并，跨批延续的相邻场景统一边界；边界参考图不能作为当前片段的新证据。长静态画面中的大量字幕会使用有上限的上下文，原始台词仍完整保留并可检索。非相邻的相似画面保留独立片段，只建立「可能相似的场景」导航，便于对照时间和画面；这种关联不认定为相同地点、人物或事件。

完整分块方案先发布为可检索的初步结果，再按时间顺序深入分析复杂动作、身份不明或图文冲突等片段。自动深入理解读取代表帧和模型选出的重要变化原帧；旧响应或空选择会保守回退到全部原帧。API 每批最多 24 张当前画面，Codex CLI 每批最多 12 张，另加最多 8 张角色参考图；超过上限拆成子批，已确认的角色 ID 可在子批间沿用。全部原帧仍保留，手动补查会逐批读取该片段全部原帧。此前深入理解改变剧情上下文时，后续简单片段使用 `preparation` 更新文字理解，不重复发送图片。

每块保存有来源的输入／输出记忆，分别保存画面事实、台词事实和综合推断。记忆有长度上限；同项目内按已填写的季／集顺序沿用此前完整、有效的场景资料，缺集和未完成区间记录缺口，未编号视频不推断跨集先后。旧画面、对白或推断不能证明当前画面发生了某个动作。

搜索和作品详情中的「深入分析此片段」会创建独立持久任务。补查沿用原 `chunk_id` 与时间边界，升级当前版本并保留收藏、引用和历史版本；原视频当前仍须可访问。改台词、改角色或修改此前场景理解后，受影响的结果显示「上下文待更新」，不会自动启动整集／整剧付费重跑。作品详情先显示最多 8 张代表原帧，可每次展开另外 24 张；搜索中的台词来源可直接跳转到对应字幕和时间。

任务队列分别显示台词整理、视觉分块、深入理解、更新连续理解的请求、耗时和缓存复用。深入分析和文字更新数量在分块后确定，因此初始估算显示范围；减少请求数不等同于已证明运行时间减少。同素材、同 Codex 配置的 28.445 秒样本，模型耗时由 331.934 秒降至 147.874 秒（**降低 55.5%**），四类八条检索样本均命中；这不代表整片都有同等提速。完整计时口径及调试失败记录见[验证记录](docs/VALIDATION.md)。

## 按阶段选择并行或串行

在分析窗口中，台词整理、视觉分块和画面字幕 OCR 分别提供「并行／串行」选择，最多允许 **1–8 路**。新任务默认三部分并行、任务上限 **3 路**；实际同时请求数还受对应模型连接的「最大并发」限制，例如连接上限为 2 时最多两路。可以在「模型与设置 → 分析默认值」保存偏好，每次任务也能单独调整。修改选择后需重新估算；任务队列显示创建时保存的执行方式，恢复／重试沿用该选择。旧任务及未指定执行方式的直接 API 请求保持串行。

并行台词批次使用同一份此前剧情记忆，以及有上限的相邻原始台词；并行视觉批次使用此前剧情记忆与前批边界原帧。结果按原时间轴汇总、合并相邻延续场景，因此返回先后不会改变字幕或场景顺序。串行模式会逐批使用此前批次的理解，适合需要更多连续推理的内容。并行和串行可能得到不同的简要理解；切换方式不会把依赖不同的结果误当成相同缓存。

复杂片段深入理解、后续连续理解更新及剧集间处理仍按顺序执行，以沿用已确认的剧情和角色。角色重识别也可选择准备阶段的执行方式；单片段深入分析按依赖顺序读取原帧。并行请求共同占用每集的累计预算，每个在途请求预留最多三次尝试；预算不足时停止派发并保留已完成结果。暂停／取消会停止新批次，已经发出的请求先收尾保存，因此可能需要等待模型返回。服务中断后，成功回执复用，无法确认的在途尝试保守计入预算。

并行降低的是可独立请求的等待时间，不减少必需请求数，也不保证服务限流或额度不足时提速。工程并行与恢复检查见[验证记录](docs/VALIDATION.md)。

## 剧集项目、文件夹与批量任务

资料库使用「文件夹 → 项目 → 视频」结构。文件夹可嵌套，一部剧或动画作为一个项目；每个项目可添加多个标签。视频可在导入时归类，也可在资料库勾选后统一移入项目或移至「未归类」。文件夹只管理资料库中的组织关系，不搬动磁盘上的原视频。

项目支持改名、移动和标签编辑；删除项目会将成员视频转为未归类，保留分析和收藏。删除文件夹时，子文件夹和项目移到上一级。检索可限定项目、文件夹（包含下级文件夹）及标签。

批量导入在后台逐集处理，一集失败不会撤销已成功的项目。任务队列保留每项结果，刷新或重启后可修改失败项再重试；重复视频会链接已有资产，不改变其原有归属或字幕。导入与本地关键帧扫描不调用模型，导入后不会自动启动付费分析。

批量分析按项目、季、集排序，底层仍是每集独立任务：每集使用自己的累计请求／费用上限，整批显示估算合计与执行进度。任何一集费用未知时，整批金额也显示未知。旧版定时采样及 `content-keyframes-v1` 任务保留原策略、配置与成功产物；界面新任务采用分块策略，不改变本地选帧算法，也不增加全局任务并发。

若旧版本在扫描结束后提示「无法提取计划指定的精确画面；未用相邻帧替代」，更新代码并重启本地服务，再使用新启动链接打开页面、点击「扫描关键帧」重试。已修复批量候选帧较多时 FFmpeg 选择表达式过深、无法生成预览的问题；扫描和重试均不调用模型。若仍失败，请保留任务错误及服务终端日志，继续排查原片解码或时间戳问题。

## 删除视频与分类

视频卡片和详情页可删除单个视频，也可在资料库勾选后批量删除。项目、文件夹的删除窗口会说明影响范围：默认仅删除分类、保留视频；也可选择同时删除其中的视频，文件夹范围包含下级文件夹。

删除视频时有两种方式，默认只删除应用内资料：

- **仅删除应用内资料**：从资料库、检索、收藏列表和当前角色证据中移除视频，磁盘原视频不动。视频及其分析、字幕、人工修改保存在应用回收站，可恢复。
- **同时删除源视频文件**：明确确认文件清单后删除登记的源视频。源文件删除不可撤销；恢复应用资料不会重新生成原视频。外挂字幕原文件不会随之删除。

删除操作先核对影响范围和任务状态；源文件删除还会校验文件是否变化、是否被其他视频记录共用。失败原因会逐项显示，不把部分成功报告成全部完成。回收站恢复不会覆盖冲突文件或已有分类；旧分析任务不会因恢复视频自动重跑。

## 跨镜头角色档案（0.2）

画面分析会按时间推进，先参考已有角色档案和证据画面，再判断当前人物是否已经登场；没有匹配时建立新档案，后续识别继续积累外观与出场证据。支持真人和动画角色，姓名未知时使用待确认的角色标识，不根据演员常识猜名字。

同一项目内的影片共享角色档案，跨季、跨集沿用。项目使用稳定身份，改名和移动文件夹不会改变角色关联。首次升级会按原有「类型＋系列名称」（忽略大小写及多余空格）建立项目，无系列视频保留在未归类中。

跨项目移动视频会保留历史观察和人工修订，并将相关角色映射至目标项目；不同来源的同名角色不会自动合并。历史档案保留，但当前模型参考图只使用当前项目成员的有效出场。相关画面任务正在运行时需先暂停或等待结束再移动；归属改变后的旧排队任务需重新创建，已有识别结果仍然保留。

在作品详情打开「角色档案」：

1. 查看每个角色的「当前形象」：使用最新出场的实际证据图，模型能确定人物范围时截取角色本人，否则显示完整画面。点击形象图查看原始证据，或从出场记录的时间码回到原片。图片不会通过生成模型补画。
2. 编辑姓名、别名、外观描述、已积累的外观特征和备注。人工修订会保留；姓名和别名同步用于镜头检索。
3. 将重复识别的档案合并到保留的角色，或删除错误档案。合并会统一出场关联；删除会解除关联，但保留原始识别资料和证据。再次识别仍可能为真实出现但未匹配的人物新建档案。
4. 点击「按档案重新识别」，选择本集或同系列全部已导入剧集，估算用量并设置每集预算后开始。系统使用最新修订档案重新分析完整画面，保留字幕、人工笔记及旧分析版本。旧版 0.1 的记录也可通过此入口建立角色档案。

重新识别会调用已绑定的视觉模型并产生用量，整剧处理按季／集排序。所有选中原视频需可访问。识别过程中再次修改档案，会阻止旧档案任务继续提交过期结果；请从角色档案页重新发起识别。自动关联仍可能认错或拆成多个角色，真实影视准确率需要结合所选模型验收。

## 使用 Codex 订阅

在**运行 SceneRecall 后端的机器和系统用户下**安装 Codex CLI **0.155.1 或更新版本**，然后使用自己的 ChatGPT 账户登录：

```sh
npm install -g @openai/codex
codex login
codex login status
```

登录时选择 ChatGPT 账户；账户需具备可用的 Codex 订阅权益与额度。已有 CLI 时可用同一安装命令更新。SceneRecall 复用 CLI 自己管理的登录状态，不读取、复制或保存 `auth.json`，也不要求把订阅凭据转换成 API Key。安装与登录细节见 [Codex CLI 文档](https://learn.chatgpt.com/docs/cli)和 [Codex 身份验证文档](https://learn.chatgpt.com/docs/auth)。

在「模型与设置」新增 Codex CLI 连接，检查 CLI 安装和登录状态。无需填写 Base URL 或 API Key；模型 ID 可以留空，使用 CLI 内置默认模型，也可填写当前账户可用的模型。应用调用采用独立临时目录并忽略个人 CLI 配置与规则；若平时使用自选模型，请在连接中明确填写模型 ID。保存连接后，为需要的能力分别执行连接测试并保存能力分配。状态检查不执行模型推理，能力测试会实际消耗账户额度。

本地路由 `GET /api/codex/status` 和其他 API 一样受 SceneRecall 会话保护。识别请求仍经过本地后端，由后端调用 `codex exec`，不需要另开 CLI 代理服务。若服务找不到可执行文件，可在启动前设置 `SCENERECALL_CODEX_PATH` 为 Codex 可执行文件的绝对路径。远程部署或 Docker 中运行后端时，CLI 也必须安装并登录在对应的后端环境；浏览器所在电脑的登录状态不会自动传入容器或远程机器。

开始单个／批量分析、角色重识别或片段深入分析前，可以在任务窗口按阶段选择 **Codex 模型与思考等级**。各阶段沿用已绑定的连接，可继承连接模型、选择 Codex 内置默认或从模型列表选择；思考等级随所选模型的支持情况变化。修改选择后需重新估算。本次选择随任务保存，不改全局连接；暂停、恢复和重试沿用保存的选择，改用其他模型请新建任务。API 来源本轮仍沿用连接设置。

模型列表由受会话保护的 `GET /api/codex/models` 读取运行后端用户的 `CODEX_HOME/models_cache.json`（默认 `~/.codex/models_cache.json`）中的可见模型元数据，不读取认证文件，也不调用模型。列表反映本机 Codex 缓存，账户实际可用性以执行时为准；缓存缺失或损坏时会显示说明，可继续沿用连接／内置默认，使用 Codex 更新模型缓存后点击重试。显式模型与思考等级参与结果缓存标识，避免不同设置复用不匹配的识别结果。

Codex CLI 会将所需文字和采样图发送给 OpenAI，这不是离线推理。订阅额度和限额由 Codex 账户管理；SceneRecall 的请求数预算仍然生效，但不会将订阅调用显示为 0 美元，也无法换算美元金额预算。使用 Codex CLI 分析时请将费用预算留空；额度耗尽后按任务错误提示处理，再恢复或重试任务。自动向量索引若绑定其他 API，仍可能产生独立的 API 费用。

## 字幕、采样与费用

- **容器文本字幕轨**：MKV、MP4 等容器中的 ASS、SSA、SubRip、WebVTT、mov_text 等可解码文本轨在本机通过 FFmpeg 提取，保存提取文件、来源轨道信息及相对视频起点的时间轴，导入后即可进行字面检索。可在导入前选择轨道，也可在作品详情为已导入视频提取或切换轨道；历史字幕文件和收藏保留。提取不调用模型，也不自动建立付费语义向量。PGS／DVD 等位图软字幕不能直接提取文本，会提示使用外挂字幕；只有字幕确实烧录进画面时才适用现有 OCR。
- **外挂字幕**：支持 SRT、VTT、ASS；保存原文件和原文。导入时可设置正负时间偏移，超出视频范围或损坏的字幕会被拒绝。
- **画面内嵌字幕**：默认每秒 2 帧、裁剪底部 35%，可调整区域；使用独立绑定的视觉 API 或 Codex CLI 连接。连续相同字幕合并，空帧和间隔后的重复保留边界；双语分开保存，无法辨认的文字标记待复核，不凭空补写。
- **画面分析**：本地逐帧低分辨率扫描镜头与内容变化，合并近重复持帧，优先选择稳定姿态、清晰构图和明显动作变化，降低模糊过渡画面的权重。每个镜头至少保留一张可用代表帧，不以固定秒数补帧。新分块流程使用上述 56＋8 拼图，自动深入理解选择代表／重要变化原帧，按 API 最多 24 张或 Codex CLI 最多 12 张原帧分批；旧 `content-keyframes-v1` 仍按最多八张且不跨镜头的计划运行。精确源时间戳随计划保存，证据始终指向真实原帧。
- **关键帧边界**：这里的关键帧是成片中的代表性画面，不等同于编码 I 帧，也不保证还原制作工序中的原画。局部微小动作和极短姿态仍可能漏选；扫描和模型的真实动画质量需结合素材验收。字幕 OCR 独立采样，以免静止画面中的台词变化被漏掉。
- **用量**：先扫描并展示实际选中的帧数，再估算各阶段请求和费用范围。扫描可后台运行、取消和重试，完成计划可复用。API 配置单价后以 USD / 百万 token 计算估算；缺少价格或供应商用量时费用显示未知，Codex CLI 的订阅费用也保持未知。重试、角色档案增长、连续理解文字更新及向量索引会改变实际用量；重试和向量索引不计入分块估算范围。
- **预算**：请求和费用预算不足时暂停新增调用；每次调用会预留最多三次尝试。已发出的请求可能已产生费用，取消无法撤销供应商计费。任务队列中的「恢复／重试」支持调整累计预算并复用成功产物；请求预算至少要为下一次调用留出三次尝试。中断后费用不完整时，核对供应商账单再决定是否移除费用限制；请求次数限制继续生效。

更换查询／决策／解释模型不会重跑识别。更换 embedding 模型后，在「本地数据」重建语义向量索引；只处理现有文本。切换分块、画面或字幕模型后，按需新建任务。分块缓存绑定视频、关键帧计划、字幕及人工语义修订、模型、提示词版本、角色／项目修订和输入记忆；成功结果先保存回执，恢复时重放，不重复计入用量。前块失败会停止依赖链。已有任务保存模型配置快照；连接类型、模型地址或名称变化后请创建新任务，单独更新密钥、单价或并发设置不使成功识别缓存失效。

## 本地资料、隐私和恢复

API Key 仅由后端使用，支持当前服务会话、系统凭据库、环境变量及无需 Key 四种方式。界面默认会话保存，重启后需重新填写；需要持久保存时选择系统凭据库。环境变量模式只保存变量名，启动服务前需设置该变量。Key 不写入资料文件、浏览器持久存储或备份。

选择远端 API 时，相应采样图、字幕裁剪图或检索文本会发往用户填写的 Base URL；选择 Codex CLI 时由 CLI 发往 OpenAI。本地存储不意味着这些模型请求离线。原视频不整片上传，识别结果和证据图留在本机。提供无 Key 的本地兼容接口时可完全在本机运行这些能力。

```text
资料库/
  library.json
  organization/                  项目、嵌套文件夹、标签与历史角色归属映射
  works/                         作品信息、共享角色档案及合并／删除映射
  assets/<asset_id>/
    manifest.json                视频属性和内容指纹
    active-analysis.json         当前有效结果的引用
    frames/                      证据帧与注册表
    keyframe-plans/               内容选帧计划、精确时间戳及模型分批
    subtitles/                   外挂／容器字幕提取文件和解析结果
    analyses/<run_id>/           运行信息、观察记录、OCR 结果
      scenes/                   不可变场景版本及输入／输出记忆
      scene-inputs/             冻结的分阶段模型输入
      scene-receipts/           已完成请求及用量回执
      scene-deep/               深入理解及角色子批恢复资料
    annotations/                 人工纠错、姓名、笔记和收藏
    proxy/                       按需生成的浏览器播放代理
  indexes/                       可重建的字面和向量索引
  runtime/                       持久任务队列和生成的备份
  private/                       模型设置及本机视频路径映射
```

「本地数据」可以生成 ZIP 备份：默认包含资料、证据帧、场景历史版本与人工注释，不含原视频、API Key、原片路径映射、任务队列及索引。备份包含分块输入、回执与子批恢复资料；这些资料可能含本机证据帧路径，但不含凭证。场景收藏继续支持 Markdown／JSON 引用导出。勾选「同时包含原视频」生成完整备份，要求所有原视频在线。恢复只支持 ZIP，先检查路径、场景原帧／字幕和连续记忆来源引用，再合并；存在冲突时不覆盖现有文件。模型连接需要另行配置，索引可重新生成。

原视频移动后，在作品详情点击「定位原文件」；应用按内容指纹验证，不能把另一剪辑版替换到旧时间轴。文件大小或修改时间变化时，也会暂停读取原片并要求重新定位校验；内容相同则可以恢复使用。原视频离线时仍能查看已保存文字及证据帧。如果浏览器不支持视频编码，可生成 H.264 / AAC 播放代理，占用额外磁盘空间，原片保持不变。

需要前端热更新时，保持后端在 8765 运行，在 `frontend` 中运行 `npm run dev`，打开 `http://127.0.0.1:5173/?token=后端打印的令牌`。Vite 默认将 `/api` 代理到本机 8765；后端改端口时也要修改 Vite 代理配置。
