# 角色确认与识别名单

角色确认界面允许先核对不同角色的候选，再统一提交。它沿用已有的人工作品范围、参考图库和确认接口，不会因为候选排名或点击提交而推断其他镜头的身份。

## 先选要识别的角色

1. 在作品详情打开「角色档案 → 开始角色确认」。任务已处于「等待确认」时，也可以从任务队列点击「确认角色并继续」。
2. 在窗口顶部点击「选择识别角色」。可按中文名、日文名或别名查找，逐个勾选，也可使用「全选角色」或「清空名单」。全选和清空作用于整份名单。
3. 点击「保存识别名单」。标注界面只显示入选角色，待确认数也只统计这些角色。若名单为空，可以直接点击「继续任务」执行后续分析。

已有档案和新导入的角色默认勾选。Bangumi 的主角、配角标记不决定谁入选。选择随角色库保存，使用同一角色库的剧集共用。移出角色会清除该角色尚未提交的裁剪勾选，已经确认的参考和出场记录仍可在档案中查看。以后重新勾选即可沿用已保存的标注。

「暂时跳过这个角色」用于角色仍在识别名单、但目前没有合适裁剪的情况。若后续自动识别也要排除该角色，请在识别名单中取消勾选。

## 勾选与提交

- 切换角色或重新读取进度时，尚未提交的勾选保留。可以提交当前角色的所选裁剪，也可以使用「提交全部已核对 N 张」。
- 确认请求按提交顺序串行执行，每个角色的单次请求最多包含 3 张；保存期间可以继续切角色、预览、勾选其他未排队裁剪并追加提交。
- 否定候选、换候选、跳过角色和恢复核对也进入同一写入队列。同一裁剪不能同时为不同角色勾选或排队；尚未核实的操作会保留冲突保护。
- 每项显示排队中、保存中、已保存、保存失败或结果未确认。只有后端明确返回该项确认成功，才取消勾选并计为已保存；新补入的候选默认不勾选。

## 失败与离开页面

失败项保留逐项说明，可以单独重试；已成功项不会随该次重试重复提交。连接中断或服务器错误可能发生在写入之后，因此界面显示「结果未确认」，不猜测是否已经保存。重试沿用后端已有的幂等确认与恢复机制。

选择「暂不重试并核对进度」时，必须先成功读取后端实际进度，才解除该项保留状态；读取失败仍保留未知状态及操作门槛。外层列表刷新失败独立显示，不撤销已保存的确认。

勾选和待发送队列只保存在当前页面内存中，不是持久后台任务。排队或保存期间不能关闭确认窗口；仍有未提交勾选时须提交或明确取消。刷新或离开页面会触发浏览器提示，强行离开可能丢失未发送项。重新进入后以已写入后端的进度为准，不能把勾选或排队视为已经保存。

继续分析前须完成或取消待提交的裁剪勾选，处理保存异常，并等待保存队列和采样结束。识别名单中的角色均须确认或明确跳过。

## 候选说明

每个角色最多展示 3 张经过镜头或时间去重的已保存候选。卡片显示角色在该裁剪候选中的排名和 CCIP 距离；距离越小越相似，但不是身份置信度，排名也不是确认。排名属于已保存候选，不是覆盖整部作品的识别结论。

角色旁显示本地匹配参考数量。参考图仍需通过人物检测；没有本地参考时，增加采样不会补齐参考。同一裁剪可以出现在多个角色的待核对列表，最终身份必须由用户结合原始画面判断。

少量本地采样的界面每轮 12 帧、接口上限 24 帧和 Top-K 20 是原有能力，本次队列改动没有扩大处理范围或新增模型调用。

## 实现与验证范围

前端保存队列位于 `frontend/src/components/CharacterConfirmation.tsx`，后端候选排名和参考数量来自 `backend/scenerecall/character_confirmation.py`。现有确认接口的单角色批量上限和人工来源记录继续生效。

对应回归用例位于 `frontend/tests/character_confirmation.test.tsx` 和 `tests/test_character_confirmation.py`，覆盖跨角色草稿、串行写入、未知结果、重试冲突、离开保护及无推理读取候选等行为。本文记录实现行为与测试范围，不构成本轮真实模型、识别准确率或前端人工验收结论。
