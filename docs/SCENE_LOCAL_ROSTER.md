# 大角色名单的本地筛选与场景上下文限额

角色档案较多、别名和背景资料较长时，完整名单可能在本地视觉匹配之前就超过模型上下文限额。本功能让启用了本地视觉匹配的场景分析先检查完整允许名单，再按当前画面的人物候选选择相关档案，最后压缩实际发送给模型的档案文字。

## 生效范围

- 分析策略为 `scene-chunks-v1`，且任务快照中 `identity_settings.visual.enabled` 为真。
- 创建任务、角色确认后继续、暂停后恢复和场景请求刷新使用同一规则。
- 未启用本地视觉匹配时，仍在任务进入模型处理前校验完整名单；超过限额会明确报错，不会静默删掉后面的角色。

## 请求流程与证据边界

1. 保留完整允许名单及角色库、角色修订和素材归属修订快照。本地选择前不按名单顺序截取前若干角色。
2. 沿用当前帧的本地匹配结果，合并每个人物区域的候选角色。处于名单尾部的角色与其他角色具有相同的入选机会。
3. 在视觉准备和深入分析请求首次冻结，以及未成功请求的身份资料刷新之后，再限制选中档案的体积。
4. 档案部分继续沿用 18,000 字节预算。姓名、别名和参考资料身份边界得到保留；可重复或过长的背景文字按既有规则压缩，并保留省略标记。
5. `identity_regions`、`region_images` 和 `reference_frames` 不挤占较小的档案文字预算，也不会为使档案合规而被静默删除。整个模型上下文仍受 provider 的既有限额约束，超限时继续采用现有拆分／重试规则。

候选匹配仍是候选，不能据此确认人物实名、当前出场或动作。统一任务的人工作品角色确认门槛不变；待确认项或尚在运行的采样仍会阻止继续。角色档案在任务中途变化时，旧快照不能继续作为当前身份资料使用。

没有本地候选时会保留完整允许名单作为未确认先验。如果它仍然超过预算，请求会在模型调用前明确失败，不会通过任意截断名单继续。

## 验证

以 `f907431` 为基线，仅加入本功能涉及的 `jobs.py`、`scene_jobs.py`、`task_lifecycle.py` 和测试文件，在独立代码副本中运行：

```powershell
python -m pytest tests/test_scene_local_roster.py -q
```

7 项通过。测试覆盖 80 人名单、人工作业门槛、修订变化、串行／并行请求、名单末尾角色、无候选时零模型请求、人物区域证据保留和原有上下文拆分契约。测试使用合成资料和替代模型响应，没有处理真实视频、加载模型或访问网络。

本功能不改变 provider 限额，不引入知识库或人物裁剪 PNG 保留策略。
