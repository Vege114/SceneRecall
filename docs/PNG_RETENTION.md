# 人物裁剪 PNG 保留策略

应用仍处于开发阶段，普通人物裁剪 PNG **默认保留**，用于检查检测框、错认和测试复现。正式上线时使用 `production` 阶段，普通人物裁剪 PNG **默认不永久保留**。

这里的普通裁剪是 `assets/<asset_id>/identity/visual/crops` 下的人物检测中间产物。识别记录、特征、视频与原帧 ID、时间点、人物框、匹配候选和人工决定继续保存。可信参考图库中的独立图片、用户导出的证据图、原片和原帧不属于这个清理范围。

## 配置与上线切换

作品／资产详情的「视听身份与证据 → 视觉身份配置」可以选择普通人物 PNG 保留策略：

| 设置值 | 行为 |
| --- | --- |
| `default` | 跟随应用部署配置，开发阶段默认保留、正式阶段默认不保留 |
| `retain` | 明确保留普通 PNG，供测试与诊断使用 |
| `discard` | 不永久保留普通 PNG，预览时按需重建 |

保存配置本身不会启动识别，也不会清理其他资产。该策略在后续人物处理时生效。旧配置没有 `crop_retention` 字段时视为 `default`。

新任务会冻结创建时解析出的实际策略，暂停、恢复或切换部署阶段后仍按该策略执行。需要改用另一保留策略时，应保存配置并创建新任务；旧任务的识别参数与保存策略分别校验。

部署环境支持以下变量：

- `SCENERECALL_STAGE`：`development`、`test` 或 `production`。未设置时为 `development`；`development` 和 `test` 默认保留，`production` 默认不保留。
- `SCENERECALL_CROP_RETENTION`：`retain` 或 `discard`，覆盖部署阶段的默认值。

明确的资产设置优先于环境覆盖；环境覆盖优先于阶段默认值。正式发布应设置 `SCENERECALL_STAGE=production`，并核对没有遗留的 `SCENERECALL_CROP_RETENTION=retain` 或资产级 `retain` 诊断设置。

Windows 启动示例：

```powershell
$env:SCENERECALL_STAGE = 'production'
.\scripts\start_windows.cmd -DataDir 'D:\SceneRecallLibrary'
```

开发测试需要模拟正式存储策略时，可在待测资产选择 `discard`。不必把整个开发环境改为正式模式，也不必改变其他作品的策略。

## 缺少裁剪时的使用

不保留模式继续使用已保存的特征参与匹配，展示人物图片时使用已登记的原帧、精确人物框与校验信息重建 PNG。预览不会永久补回普通裁剪。向模型提供临时图像的路径只在本次调用期间存在，完成后清理。

人物复核、原片时间点跳转和检索继续引用持久的区域记录。人工确认并提升到可信参考时，参考图库保存独立图片，不依赖普通裁剪文件的存活。

元数据备份仍保留定位与校验信息、人工决定及可信参考。恢复后没有普通 PNG 时，从随备份恢复的原帧按需重建；原帧与原片都不可用时无法凭时间戳还原图像，应显示证据缺失，不能绕过校验或把缺失证据当作已确认。

这项策略减少永久 PNG 占用，但没有对照测试时不声称提高整集识别速度。真实测试的处理范围、阶段耗时、最终裁剪数量及空间差额见[四集验证记录](PNG_VALIDATION_20261031.md)。
