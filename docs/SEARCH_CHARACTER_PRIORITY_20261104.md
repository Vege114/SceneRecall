## 后续实现记录：命中帧人物证据参与融合

以下记录的是 2026-11-04 已实现、经合成数据和接口回归验证的规则。前文“未运行模型”仅指原始只读窗口核验；后续另做过一次既有图像向量上的文本探针，以及一次发现归一化问题的真实查询，见下文。**真实查询尚未找回目标；分母修正后的页面验收另行记录，不能把规则修正视为模型召回改善。**

适用范围是查询已由本地人物名称解析器明确解析出目标，且候选记录属于 `visual` 或 `scene`。解析器保留每个目标的 `(scope_id, character_id, name)`，简称与全名指向相同的目标集合。`SearchEngine.completed_character_targets()` 供 API 在来源重建后复核；检索内部的 `_character_targets` 由服务端传递，不接受用户筛选字段直接注入。原始人物名称仍用于字幕检索、查询理解与解释；无已解析人物目标的查询，以及字幕、声音候选的融合贡献，保持原有语义。

实现位置：

- `backend/scenerecall/character_query.py`：保留解析出的目标身份。
- `backend/scenerecall/identity_bindings.py`：投影有来源依据的 `identity_region_evidence`。
- `backend/scenerecall/character_ranking.py`：同帧人物统计、无视觉命中时的身份帧定位、融合分重算。
- `backend/scenerecall/visual_index.py`：原视觉最高相似帧与精确平局规则，缓存和流式路径一致。
- `backend/scenerecall/search.py`：完整召回后的贡献加权、相对分与阈值、解释前身份限制。
- `backend/scenerecall/main.py`：按当前来源记录与最终有效命中帧再次复核。

### 身份证据来源与人数统计

`BindingResolver.resolve()` 输出 `entity.identity_region_evidence = [{region_id, frame_id}]`。该字段只投影已有身份决定的有效来源，不改变身份确认策略或模型指纹：

- 自动确认只使用该绑定决定实际接受的 `region_ids`。
- 人工确认或人工候选只使用具有对应人工决定、且指向同一人物的区域，不扩展到其他 support region。
- 自动候选只使用产生该候选决定的主 region，不把未成立的多帧支持扩成同名人物。
- 未知身份不产生有效身份帧映射；非人物实体不参与统计。

排名 helper 同时检查 `identity-binding-v2`、有效绑定 ID、人物作用域、绑定人物 ID 与实体字段一致，以及 region 属于实体声明的主/支持区域。映射帧必须属于记录和实体自己的证据帧；存在 `ordered_frames` 时，也必须属于该有序列表。

同一帧按独立 `region_id` 统计目标：同一区域不能凭两个实体或两个姓名凑成两个人；区域被不同身份或作用域冲突认领时不计入支持。同一目标的多个区域最多计一个人。确认数与候选数互斥，候选不会因为名字匹配、图文相似度或模型解释而升级为已确认。

兼容旧索引投影时，只允许 `source='retrieval-local-identity-v1'`、单一证据帧、单独主 region 且无 support region 的记录推导 region→frame。通用模型记录的宽泛 `entity.evidence_frame_ids` 不用于推断每帧都有该人物；显式空的 `identity_region_evidence` 不触发旧格式兼容。

### 命中帧保持视觉依据，缺证不代表无人

有视觉相似度结果时，仍选择窗口内 **原始 cosine 最大的帧**。其他帧即使有一个人物候选，也不能覆盖相似度更高、但检测漏人的目标帧。只有 cosine 数值完全相等，才依次用该帧的 `确认数 + 0.5 × 候选数`、不同目标人数打破平局。没有新增 soft bonus，也没有泛化文本或多查询提示参与产品排名。矩阵缓存预算保持 1 GiB。

如果候选确实没有 `hit_frame_id`，例如仅由词法或概念分支召回，则可以从已验证的 region→frame 支持中选择人物覆盖最多的真实帧；再按目标人数、时间和帧 ID 稳定选择。此时明确标为 `hit_frame_basis='character_evidence'`、`seek_basis='character_frame'`，不声称它是视觉相似度命中；只有已有有序帧提供精确时间时才填写 `seek_ms`。该路径绝不覆盖已有视觉命中帧。

`character_match` 描述的是 **最终命中帧**，不是整段窗口：

| 字段 / 状态 | 含义 |
| --- | --- |
| `required_count` | 去重后的指定人物目标数 |
| `confirmed_count` | 该帧有有效确认身份依据的目标数 |
| `candidate_count` | 该帧仅有候选身份依据的目标数，不含已确认目标 |
| `confirmed` | 该帧全部目标身份均已确认，仍不证明动作或空间关系 |
| `candidate` | 该帧覆盖全部目标，但其中至少一个仍是候选 |
| `partial` | 该帧只支持部分目标 |
| `unverified` | 该帧暂无有效指定人物支持，可能漏检，不等于无人 |

### 融合分、半权重与 75% 阈值

四路原始 RRF 贡献仍由各路名次计算：每路贡献为 `1 / (60 + rank)`。令指定目标数为 `N`，命中帧确认目标数为 `C`，候选目标数为 `U`，则人物覆盖系数为：

```text
coverage = (C + 0.5 * U) / N
effective_rrf = visual_rrf + coverage * (lexical_rrf + semantic_rrf + concept_rrf)
raw_rrf_score = visual_rrf + lexical_rrf + semantic_rrf + concept_rrf
```

该权重只约束有明确人物目标的 `visual` / `scene` 候选。候选半权重是检索排序规则，不是“身份正确率 50%”。没有命中帧人物支持时，姓名元数据带来的非视觉贡献不再保留，但 **原视觉贡献仍保留，窗口不会仅因无 region 被硬删除**。窗口 summary 或其他帧的文字不能恢复被取消的人物加分；本轮没有保留窗口文字例外。

上述有效融合分在完整召回集合上计算，之后才归一化和筛选：

```text
reference = max(raw_rrf_score over the complete fused candidate set)
match_score = clamp(100 * effective_rrf / reference, 0, 100)
keep exactly match_score > min_match_score
```

零基准时分数为 0。人物阈值检索的分母固定为完整召回集合中、人物证据扣分前的原始 RRF 最高分，不用扣分后的最高有效分重新拉到 100%。适用的新基准名为 `character_grounded_rrf_v1`；没有此人物加权的检索仍为 `relative_rrf_v1`。75% 仍是严格大于，阈值模式继续使用完整本地候选，不恢复前 10/50 条截断；结果按最终匹配分降序、ID 稳定打破平局。`raw_rrf_score` 保留未加权原分，便于审计。无人物目标的查询，以及未设置阈值的 legacy `limit` 调用，保持此前分母行为。

相对分衡量有效融合分相对本次完整候选原始最高分的比例，最高有效结果可以低于 75%，也可以全部被过滤；100% 不再是剩余第一名自动获得的值。即使出现 100%，也不能由该分数推出实名已确认、两人确实同时可见或“人在塔上”成立；身份状态仍由 `character_match` 独立表达。

### canonical 重核验与解释约束

候选内部保存 `_rrf_contributions` 和 `_match_score_reference`；这些私有字段不透传到最终 API。来源重建后，API 先验证最终命中帧，再用当前 canonical 记录重新计算 `character_match` 和人物加权分；已撤销、错作用域或不再属于命中帧的身份依据不能维持旧加分。

阈值模式重算相对分时使用 **本次完整召回原分母**，不会按剩余结果重新归一化。最终再执行严格 `>75`、降序排序，并更新 `selection.returned_count`。因此身份复核后排名或最高显示分可能下降，剩余最高项不必重新变成 100%。

引擎在模型重排之后、生成解释之前，强制未全部确认命中帧身份的记录最多为 `partial`。canonical 复核也施加该限制；当前人物摘要、分数或匹配类型变化会使旧解释失效。全部身份确认本身仍不足以证明查询要求的动作与空间关系。

开启可选 `visual_verification` 时，其返回结果还会经过最终守卫：不能将 `character_match` 尚未全部确认的记录升级为 `full`，发生此类修正时旧解释也失效。这防止视觉复核模型越过实名身份依据，不表示动作、人数或空间关系已经被完整识别。

### 首次真实验收暴露的分母问题及修正

首次人物加权版本以原姓名查询在全集、75 阈值下实际返回 21 条，全部 `character_match=unverified`，次序退化为纯视觉排名；E01 已知目标仍未进入结果。这次验收没有达到找回目标的要求。原因之一是使用 `max(effective_rrf)` 重新归一化：跨帧姓名贡献虽已扣除，但剩下的塔背景最高项又被拉回 100%，削弱了扣分对阈值的实际作用。

本次只将人物阈值模式的分母改为完整召回原始 RRF 最高值；有效分公式、候选半权重、原视觉帧和 1 GiB 缓存预算均不变。空结果如经页面验收确认，证明扣分不再被重新归一化抵消，不能证明小人物已被检出、空间关系模型已改善或目标已被召回。
