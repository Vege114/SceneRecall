# v0.2 implementation contract

Internal records and REST use snake_case. Time is integer milliseconds relative to asset start. Source data are versioned JSON; all indexes disposable. No reads/frames/model calls on `测试用视频` during development.

## Projects, folders and migration (2026-10-13)

`Library.organization` is an `OrganizationStore`. `organization/catalog.json` stores `organization_version=1`, stable projects, folders, per-asset membership and historical character mappings. Projects have `id,name,kind,folder_id,tags`; folders have `id,name,parent_id`. A video belongs to zero or one project. Folder ancestry cannot contain cycles. Folder deletion reparents direct children/projects; project deletion unassigns member videos without deleting source data. Existing `work_id` and immutable observations are unchanged.

`GET/POST /api/projects`, `PATCH/DELETE /api/projects/{id}`, `GET/POST /api/folders`, `PATCH/DELETE /api/folders/{id}` manage organization. `POST /api/projects/assign` accepts `{asset_ids,project_id}` (null unassigns). Project responses include `asset_count`. Asset projections include `project_id,project_name,folder_id,folder_ids,tags,membership_revision,character_scope_id`. Search supports `project_id`, `folder_id` (descendants included), and `tag` alongside existing filters.

First migration groups legacy assets by normalized kind/series and preserves their original cast scopes. New project scopes are stable across renames. Moving assets maps historical `(scope,character_id)` into the destination registry, copying relevant human fields and respecting redirects/tombstones. Exact source identity can be reused; names alone never merge identities. Source registries remain archived. Current reference pictures and appearances must belong to current members. Organization and registry changes publish through a durable after-image journal; startup rolls it forward before serving requests. Running vision work in either affected scope blocks reassignment; queued/paused jobs become stale. New vision snapshots include membership revision and cannot resume after reassignment.

Backup includes organization and historical identity maps. Restore validates the complete graph, upgrades legacy backups in staging, merges nonconflicting organization records, and rejects conflicting identities without overwriting them. A durable restore journal is written before any asset publication; startup completes interrupted file publication before organization migration, retaining staging until completion. Keyframe plans validate frame references, ranges and precise timestamps; incomplete plans need a new local scan because runtime jobs are not backed up.

## Deletion, source files and restoration

Video cards, asset detail and bulk selection support deletion. Projects/folders retain their default non-cascading behavior: deleting a project unassigns its videos; deleting a folder reparents its immediate contents. `delete_contents=true` also removes the selected project's videos, or the entire selected folder subtree including projects and videos. All application-data deletions are retained in a persistent recycle bin. Deleted videos are excluded from active library/search/favorites, model reference pictures and ordinary asset/frame/plan access; their evidence remains available for restoration and backup validation.

`POST /api/deletions/preview` accepts `{kind:assets|project|folder,asset_ids?,id?,delete_contents=false,delete_source=false}`. It returns `token,title,asset_count,project_count,folder_count,assets:[{id,title}],projects:[{id,name}],folders:[{id,name}],blocked_jobs,source_files,source_file_count,delete_source,source_files_preserved`. Deletion responses expose source paths only in this authenticated preview; public trash entries omit them. The token binds the confirmation to the selected scope and source state.

`DELETE /api/assets/{id}?expected_token=...&delete_source=false` deletes one asset; `POST /api/assets/delete` accepts `{asset_ids,expected_token?,delete_source=false}`. `DELETE /api/projects/{id}` and `DELETE /api/folders/{id}` accept `delete_contents`, `delete_source` and `expected_token` query parameters. The UI always sends its current preview token and refreshes the preview when the deletion mode changes. Responses contain `{trash,deleted_asset_ids,deleted_project_ids,deleted_folder_ids}`. Running work blocks unsafe deletion; stale queued work cannot recreate deleted videos or resume against a changed membership.

`delete_source=false` leaves original media untouched. With `delete_source=true`, source deletion is permanent, requires `expected_token`, and is explicitly confirmed separately from application-data deletion. Preflight checks the registered file identity/content and rejects missing, changed, unsafe or shared sources before modifying application data. After preflight, the application deletion and per-source pending intents are durably stored before unlinking each source. Long content checks run outside the library lock; immediately before unlink, current sharing and file identity are rechecked under that lock. `trash.source_results` records `pending|deleted|error` and the affected asset IDs; partial source failures remain visible and are never reported as complete success. Interrupted pending operations become uncertain errors and are never automatically replayed. A later file at the same pathname is not permission to delete it. Original external subtitle files are not removed.

`GET /api/trash` lists deletion groups with `id,kind,title,deleted_at,asset_count,project_count,folder_count,assets,projects,folders,delete_contents,delete_source,source_results`. `POST /api/trash/{id}/restore` returns `{restored,restored_asset_ids,restored_project_ids,restored_folder_ids}`. Restoring application data does not regenerate permanently deleted source media or automatically restart old tasks. Stable identities and retained analysis/annotations are preserved; conflicting changes are rejected without overwriting current data.

## Local selection and durable batches

`POST /api/local-files/list` accepts `{path?,kind:video|subtitle,offset=0,limit=200}` and returns `{directory,parent,entries:[{name,path,type:directory|file}],next_offset,total}`. It lists immediate children, naturally sorted, with pagination; hidden entries and non-regular/unreadable files are omitted. Paths are normalized; this is an authenticated backend-host selector, not an arbitrary file-content endpoint. No videos are uploaded by selection.

`POST /api/imports` accepts `{request_id,project_id?,items:[{item_id,...AssetInput}]}` and returns a persistent import Job. Top-level project assignment, when present, applies to every item. Public `items` contain `item_id,name,status,asset_id?,error?`, where status is pending/running/completed/existing/failed. Each file commits independently; duplicates return the existing asset without moving it. `GET /api/imports/{id}` returns `{job,items,project_id}` with authenticated input configurations for editing (common project or null). Paths remain absent from ordinary job summaries and backups. `POST /api/imports/{id}/retry` accepts `{items:[corrected item inputs]}` for unsuccessful items only. If the asset was already published before a progress/index failure, only the original configuration may be retried; changing that item cannot relabel an already imported video.

Batch submission idempotency uses request ID plus payload digest in SQLite; same ID/different content returns 409. Each import item also stores its stable `import_item_key` with the atomically published asset so a crash before progress persistence cannot import it twice. Failed items do not stop later files. Import and local subtitle extraction never call providers.

`POST /api/jobs/batch/estimate` accepts `{items:[AnalysisInput]}` and returns per-asset estimates plus summed frames/requests/cost and warnings. Any unknown member cost makes the total unknown. `POST /api/jobs/batch` accepts `{request_id,items:[AnalysisInput]}` and atomically returns `{batch_id,jobs}` in project/season/episode order. Budgets remain per episode; successful outputs and cumulative usage remain on each job. `POST /api/jobs/batches/{batch_id}/{pause|resume|cancel|retry}` controls eligible members and returns `{jobs,failures}`. Duplicate analysis submissions cannot create another group.

## Content keyframe plans

New vision tasks use `sampling_strategy=content-keyframes-v1`. A single low-resolution decoding pass detects cuts and combines five-pose local comparison, near-duplicate collapse, held-pose preference (80 ms), visual novelty and sharpness. [PySceneDetect ContentDetector](https://www.scenedetect.com/docs/latest/api/detectors.html#contentdetector) continues to detect cuts from adjacent-frame color/intensity changes; representative selection is a separate content scoring step. Continuous motion uses content changes, not periodic sampling. Every detected shot has at least one usable representative. This selects representative finished-video pictures, not codec I-frames or guaranteed original animation drawings. OCR remains independent.

`POST /api/keyframe-plans` accepts `{asset_id,start_ms=0,end_ms?}` and returns a reusable plan with `id/plan_id,job_id,status`; `GET /api/keyframe-plans/{id}` adds progress and, when complete, frames with preview URLs plus shots/batches/frame_count/batch_count. Scanning is a persistent `keyframe_scan` job without model configuration or model calls. Same fingerprint/range/algorithm reuses a completed plan. Cancelled/failed scans can be retried; completed plan publication is atomic. Decoder cancellation joins worker threads and reaps FFmpeg. Interrupted local scans may restart.

`media.scan_keyframes(path,start_ms,end_ms,checkpoint=None,progress=None)` returns `{algorithm,algorithm_parameters,shots,frames,batches}`. The algorithm's thresholds and feature settings are stored with the plan, not exposed as user tuning controls. Frames preserve relative `pts,time_base`, original `source_pts,source_time_base`, rounded `at_ms`, `shot_id` and `reason`. `media.extract_keyframes(path,frames,out_paths,checkpoint=None)` matches precise source PTS, verifies actual decoded timestamps and never silently substitutes the next frame. Extraction is bounded to 256 pictures per call; workflow preparation uses chunks of 128.

Each model batch contains at most eight chronological selected frames, never crosses a shot, and has content-derived contiguous coverage boundaries. Coverage is not a claim of observing every intervening instant. Persisted plans live at `assets/<id>/keyframe-plans/<plan_id>.json`, and previews use the existing registered evidence-frame route. Cache identity includes plan, algorithm and exact selected timestamps; provenance records the selection.

`AnalysisInput.keyframe_plan_id` is optional for creation, required for a vision estimate: `/jobs/estimate` only reads completed matching plans. A direct new `/jobs` request without a plan performs local content scanning before any model request. Deprecated `window_ms/frames_per_window` are accepted but ignored by new vision tasks; estimates and created jobs return deprecation warnings. Stored pre-upgrade jobs without a strategy remain `uniform-v1`, with original checkpoints and an explicit UI label. Character reanalysis accepts `keyframe_plan_ids:{asset_id:plan_id}` and follows the same new-task rule.

## Media/subtitles module (agent owned)

`media.probe(path: Path) -> dict` returns duration_ms, width, height, video_codec, audio_codec, format_name, streams. `fingerprint(path)->str` SHA256. `detect_shots(path,start_ms,end_ms)->list[dict]` returns id,start_ms,end_ms. `make_windows(shots,max_ms=6000)->list[dict]` id,shot_id,start_ms,end_ms. `extract_frame(path,at_ms,out_path,crop=None)->dict` id/path/at_ms (crop normalized x,y,width,height optional). `sample_times(start_ms,end_ms,count=4)->list[int]`. `create_proxy(path,out_path)->None` ffmpeg. `subtitles.parse_subtitles(path,duration_ms,offset_ms=0)->list[dict]` id,start_ms,end_ms,text,language,source,review_status. Validate required file/content and time bounds. `subtitles.merge_ocr_frames(frames,sample_interval_ms=500)->list[dict]`: frames [{frame_id,at_ms,lines:[{text,language,uncertain}],...}], empty frames break repeat runs; nonconsecutive repeated lines remain separate. `subtitles.candidate_frames(frames)->list[dict]` optional visual dedup retaining evidence/timing mapping. Source language best effort und where unknown, never translation.

## Container subtitle extraction

`media.subtitle_tracks(metadata)` reports all subtitle streams using the global stream `index`, `codec`, `language`, `title`, `default`, `forced`, `supported` and an optional unsupported reason. `media.extract_subtitle_track(source,stream_index,output,metadata=None)` returns the actual extracted path (ASS/SSA -> `.ass`, other supported text -> `.srt`). Times in this extraction are relative to the same playback origin as `media.probe.start_time_ms`. `subtitles.parse_container_subtitles(path,duration_ms,offset_ms=0)` preserves text and language groups, skips drawing/comment/empty events, and records any boundary clipping for review. External subtitle parsing remains strict.

`POST /api/media/subtitle-tracks` accepts `{video_path}` and returns `{tracks,recommended_stream_index,duration_ms}`. `GET /api/assets/{id}/subtitle-tracks` returns the same for a registered, available source. `POST /api/assets/{id}/subtitles/extract` accepts `{subtitle_stream_index?,subtitle_offset_ms=0}` to extract or switch a container track on an existing OCR/container asset and refresh lexical search. All routes require the normal local session; no providers or automatic embeddings are invoked.

Auto import chooses a supported text track deterministically by default disposition, non-forced disposition and global index; an explicit index must identify a supported subtitle stream. No tracks resolves to legacy `embedded` with a fallback explanation, deferring OCR model configuration until analysis. Bitmap-only or failed text extraction raises an error, never silently calls OCR. The legacy `embedded` mode still means burned-in frame text; it does not render soft bitmap subtitles. `external` remains the user's supplied file. OCR jobs are refused for extracted text, including older jobs queued before conversion.

Each successful extraction stores its source file, `analyses/<run_id>/subtitles.jsonl`, run metadata, and an atomic `active-analysis.json.container_subtitles` pointer. Cues carry `source=container`, source stream index/codec/language/title, offset, asset and run identity. Only the selected container track is projected into detail/search; old OCR and container runs and annotations remain available as history. Existing collections, backup/restore and offline reading retain these records. Re-extracting the same track with unchanged content/timing keeps stable cue identity.

## Character dossiers

`CharacterStore(library)` stores `works/<scope_id>/characters.json` atomically. Scope comes from stable organization membership; the legacy normalized-series/work scope is retained as a historical source during migration. Dossiers contain stable IDs, names, aliases, descriptions, notes, observed traits and evidence. Human edits and membership changes increment revision; machine enrichment preserves edited fields. Original observations remain immutable; historical mappings, merge redirects and deletion tombstones resolve in current projections, search and appearances. Profiles and reference frames are included in normal backup/restore validation.

`GET /api/assets/{id}/characters` -> {scope_id,revision,profiles,assets}. Profiles include id,name,aliases,description,notes,appearance,user_edited,representative,appearances,appearance_count. `PATCH /api/assets/{id}/characters/{character_id}` accepts optional name,aliases,description,notes,appearance and expected_revision. `DELETE` same route accepts optional expected_revision query. `POST /api/assets/{id}/characters/{character_id}/merge` accepts target_id,expected_revision. Stale manual revisions return HTTP 409. All profile operations are scoped to the asset and refresh lexical search across related episodes.

`GET /api/assets/{id}/characters/{character_id}/portrait` returns a JPEG from the latest active chronological appearance, with a validated normalized [x,y,width,height] crop when supplied by the vision model; otherwise returns the full evidence frame. Maximum output dimension 768px; source evidence stays unchanged. Entity portrait_frame_id must reference current entity evidence, never a prior character-reference image. Catalog representative contains asset_id,frame_id,box optional, and the UI links the portrait to the complete source image. Unknown or deleted characters and cross-work lookups fail. No generated images are used.

`POST /api/assets/{id}/characters/reanalyze` accepts scope:asset|series,max_requests=1000,max_cost=null,expected_revision. All selected media and model settings are validated before queueing jobs, ordered by season/episode. Budgets apply per episode. Returns {jobs,revision,scope_id}. Jobs use force=true, full-duration vision only, with latest dossier revision; successful old outputs do not bypass reanalysis. An edit during queued/running work invalidates its revision before stale output can commit. The user can create a new reanalysis from current dossiers. Failed/resumed work with unchanged revision retains successful checkpoints and ordinary annotations remain independent.

`SearchEngine(index_dir:Path,providers:ProviderManager)`; async `rebuild(records:list[dict],embedding_profile_id:str|None=None)->dict`; sync `upsert(records:list[dict])->None` lexical. async `search(query:str,filters:dict|None=None,embedding_profile_id=None,query_profile_id=None,decision_profile_id=None,answer_profile_id=None,limit=10)->dict` -> results:list,degraded:list[str],explanation optional. sync `status()->dict`. Implement FTS5+Chinese normalize/exact substring+LanceDB embedding+RRF and evidence-preserving result IDs. Different embeddings independent namespaces, retain old successful index on rebuild failure.
Search record shape: id,asset_id,work_id,title,series,season,episode,version,kind=visual|subtitle,start_ms,end_ms,text,thumbnail (relative asset evidence path or null),evidence_frame_ids,record_id,source,review_status,entities/events optional,subtitle_text optional. Returned records add score,match_type=full|partial and match_reason. Can include adjacent-cue context records with explicit source IDs. Filters asset_id,work_id,kind,season,episode,character. Search must never invoke analyze/recognize.

## Core/library/jobs/API (root owned)

`Library(root:Path)` provides active record projection, immutable runs, file registration and annotations. Jobs queue in runtime/jobs.sqlite. HTTP API async providers/worker; SQLite connections per operation. App factory `create_app(data_dir:Path,start_worker=True,providers=None)`.
Job model snapshots and recognition cache identities distinguish Codex CLI from API connections. Missing provider_type remains OpenAI-compatible and preserves the legacy API identity/cache key. Switching connection type, URL, or model blocks old snapshots before another request. Codex CLI estimates retain frame/request estimates but monetary cost is unknown; analysis creation and resume/retry reject max_cost for Codex stages, and restored jobs pause before submitting a CLI request with a monetary budget. max_requests still reserves up to three attempts, and mixed API/CLI totals remain unknown if any cost is unknown.
